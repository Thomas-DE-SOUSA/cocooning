# Module notes de l'API

Adaptateurs du contexte `notes` : `NotePrismaRepository` et `FolderPrismaRepository` (`secondary/repositories/`, etat et outbox `note_event` dans une transaction, visibilite filtree par la requete ; lectures groupees et chemin recursif dans `*-prisma.query.ts`, ecritures du dossier et remontee de R16 dans `folder-prisma.writer.ts`, conflit de version par `outbox-version-conflict.ts`), `PairedCouplePrismaProvider` (`secondary/providers/`, lecture seule des tables de `pairing`, decision 0041) et leurs mappers Prisma (`secondary/mappers/`). Les use cases sont construits par `notesUseCase()` (`notes-use-case.factory.ts`) dans `notes-service.module.ts` (ceux des espaces et des dossiers dans `notes-folder-use-cases.ts`), qui fournit aussi `NoteCoupleGuardService` (decision 0006). Les controleurs (`primary/controllers/`, `ApiRouterEnum.NOTE_*`, `NOTE_SPACE_*`, `FOLDER_*`), chacun sous `@UseGuards(NoteCoupleGuard)` (`primary/couple/`) : le garde resout le couple forme du partenaire par `NoteCoupleGuardService` et le pose sur la requete, `@CurrentCouple()` le donne au controleur. Mappers `toNoteResponse`, `toNotePageResponse`, `toFolderResponse`, `toNoteSpaceContentsResponse` et `toNoteSpacesResponse` (`primary/mappers/`, dates ISO).

Dossiers IA (decision 0054) : `FolderPrismaRepository.findLineage` (chemin puis dossiers par identifiants, `readFolderLineage`), colonnes `kind`, `subject`, `card_template` relues par `folder-prisma.mapper.ts`. L'IA : `GeminiNoteCardWriter` (`secondary/providers/`) sur `GeminiInteractionsClient` (`POST` de l'API Interactions par `fetch`, cle dans l'en-tete `x-goog-api-key`, `store: false`, sans outil de recherche, reponse JSON par `response_format` puis Zod ; cle vide, refus HTTP, panne ou reponse hors schema : `NOTE_CARD_WRITER_UNAVAILABLE`, journalise par l'operation et le statut seulement) ; prompts dans `*.prompt.ts` (`folder-template.prompt.ts`, `card-writing.prompt.ts` : textes trouves seulement, `null` pour une case introuvable, candidats si plusieurs elements distincts) ; `card-writing.answer.ts` ne garde que les cases demandees et les sources fournies. La recherche : `SearxngWebSearchProvider` et `FetchWebPageReader` (`web-search-providers.ts`, `htmlToText` sans dependance), un `fetch` injectable pour leurs specs. `env.ts` du module : `WEB_SEARCH_SEARXNG_URL`, `WEB_SEARCH_TIMEOUT_MS`, `NOTE_CARD_GEMINI_API_KEY` (vide accepte), `NOTE_CARD_GEMINI_MODEL`. `NotesTestApp` remplace les trois ports par des faux (`test/notes/fake-note-card-writer.ts`, `fake-web-search.ts`) : aucune spec n'appelle le reseau.

Fiches : `NoteCardPrismaRepository` (`saveAll` en un `createMany` et un `UPDATE ... FROM unnest` filtre par couple et version, `note-card-prisma.writer.ts` ; evenements de plusieurs agregats par `appendNoteEventsOfMany` ; arbre de R22 par `readCardsInTree`, requete recursive), mappers `note-card-prisma.mapper.ts` (colonnes JSON relues par Zod, sinon `NOTE_CARD_DATA_CORRUPTED`) et `toNoteCardResponse`, `toNoteDetailResponse` ; use cases des fiches dans `notes-card-use-cases.ts`. Specs E2E : `smart-folders.e2e-spec.ts`, `note-cards.e2e-spec.ts` (`CardRequests`), `note-card-prisma-repository.e2e-spec.ts`, `folder-prisma-lineage.e2e-spec.ts`.

Modele a copier pour le prochain contexte du couple (agenda, messages) : `primary/couple/` (garde et decorateur du couple), `test/notes/` (`NotesTestApp`, une spec par route, isolation par couple et par proprietaire).
