# Prisma Rules (`@cocooning/couple-prisma`)

Prisma 7, `prisma-client` generator, driver adapter `@prisma/adapter-pg`, PostgreSQL 17. The schema is split into one file per model under `packages/couple/prisma/prisma/models/`; `schema.prisma` holds only the generator and the datasource.

## Rules

1. **One `.prisma` file per model**, kebab-case, prefixed by the context: `{context}-{aggregate}.prisma`, `{context}-{aggregate}-{child}.prisma`, `{context}-event.prisma`.
2. **Model names: PascalCase**, prefixed by the context when ambiguous (`NoteRevision`).
3. **Table names (`@@map`): snake_case.** Field names camelCase, column names (`@map`) snake_case.
4. **Every UUID: `@db.Uuid`.** Aggregate and event ids are generated by the domain (`Uuid.generateValue()`, v7, decision 0024); technical tables use `@default(uuid(7))`. Never `dbgenerated("uuid7()")`, never `gen_random_uuid()` as a default.
5. **Every string: `@db.VarChar(N)`**, explicit length. `@db.Text` only for free text without a bound (a note body), stated in a `///` comment.
6. **No Prisma `enum`.** An enumerated column is `String @db.VarChar(N)`, read back through `parseEnum()` (decision 0002).
7. **`coupleId` on every couple table**, `@db.Uuid`, leading column of every index and unique constraint (core.md rule 27, decision 0018). A table private to a partner has `ownerId`.
8. **Soft delete is opt-in.** An aggregate table has `deletedAt DateTime?`. The soft-delete extension derives the list of soft-deletable models from the DMMF (models with a `deletedAt` field); a unit spec compares it with the schema. Append-only tables (outbox) have no `deletedAt`.
9. **A uniqueness that tolerates deletion is a partial unique index** (`WHERE "deleted_at" IS NULL`), written in the migration SQL.
10. **Index every foreign key.** `onDelete: Cascade` from child to parent, `Restrict` towards the couple.
11. **Outbox table** (decision 0021): `id` = `eventId`, `coupleId`, `aggregateId`, `eventName @db.VarChar(120)`, `eventData Json @db.JsonB`, `userId`, `occurredAt`, `version`, `published Boolean @default(false)`, `publishedAt DateTime?`; `@@unique([aggregateId, version])`, `@@index([published, occurredAt])`, no foreign key to the aggregate (the event outlives it).
12. **`Json @db.JsonB`** for a complex value; `Prisma.JsonNull` for a nullable JSON field.
13. **`///` comments** explain the why of a non-obvious column (they reach the DMMF).
14. **Every table change updates the context's `docs/couple/architecture/<context>/tables.md`** in the same change.
15. **When in doubt, ASK.** Never guess a schema.

## Migrations

- Folders `<yyyymmddhhmmss>_<snake_name>/migration.sql`, timestamps unique.
- Every generated migration is read line by line before commit: `prisma migrate dev` may silently drop partial indexes or generated columns it does not model. Such a `DROP` is removed by hand.
- A NOT NULL column on a filled table: add nullable, backfill, then `SET NOT NULL`.
- An index on a filled table: `CREATE INDEX CONCURRENTLY` in a non-transactional migration.
- A migration branch never deployed may be squashed.
- Always run Prisma through the package scripts (`db:generate`, `db:migrate`, `db:deploy`, `db:seed`), never `npx prisma` by hand.

## Seeds

One file per entity under `prisma/seed/`, exporting `run(tx, { debug })` and inserting with `createMany`. `seed.ts` clears the database in `ORDERED_MODELS` order (leaves first), then runs every `run` in one transaction. `debug` comes from the environment. Adding a seed: create the file, call it from `seed.ts`, add the model to `ORDERED_MODELS` at its rank.
